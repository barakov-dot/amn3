# Карта skills и аудит применимости

Дата: 2026-09-07. Статус: `STATIC_AUDIT_COMPLETE_OPTIMIZATION_NOT_APPLIED`.
Область: только текущий AMN3/VPS-OPS-LAB и применимость доступных skills к его задачам.
Основание: просьба оператора проверить перегрузку личных skills и приступить к анализу.
Уточнение оператора: в остальные проекты не заходить. Глобальная оптимизация
личных skills, системных инструкций и плагинов исключена из текущего задания.

Это справочник и предложения, не новый SKILL.md, не AGENTS.md и не override
инструкций среды. Он не устанавливает, не отключает и не разрешает запуск skills.
Поведенческая эффективность и экономия времени/токенов не измерялись.

## Что действительно загружается

По официальной документации сначала доступны имя и описание skill; полный
SKILL.md читается при выборе, дополнительные материалы — по необходимости.
Количество установленных skills и суммарный размер их справочников сами по себе
не равны размеру контекста конкретной задачи.

- Личные директории вне `.system` в `$CODEX_HOME/skills`: `sdp-firebird`, `winui-app`.
  Это место хранения, не доказательство авторства или ручной установки.
- Системные skills находятся в `.system`; плагины — в управляемом кэше плагинов.
  Кэш не следует редактировать как собственный исходник: изменение непереносимо
  между версиями и может быть потеряно при обновлении.
- `vpn-evening-monitoring` найден в памяти, а не в активном каталоге skills этой
  задачи. Автоматическое обнаружение этого файла не подтверждено.
- Личный `$CODEX_HOME/AGENTS.md` пуст; `AGENTS.override.md` и `~/.agents/skills`
  при проверке отсутствовали. Перегрузка именно этих файлов не обнаружена.

## Карта применимости к AMN3/AMN2

Это предлагаемая маршрутизация для будущего AGENTS.md, а не замена текущих
обязательных инструкций. Наличие в карте не означает чтение всех skills заранее.

| Тип задачи | Подходящие навыки | Граница |
| --- | --- | --- |
| Статус, receipt, правка Markdown | Локальная проверка фактов, ссылок и diff; verification-before-completion при утверждении результата | Не перезапускать pytest, package verifier или VPS-проверки ради docs-only изменения |
| Новый дефект нашего кода | systematic-debugging; test-driven-development при разрешённом fix; проверка результата | Diagnosis не разрешает реализацию. Новый тест отвечает на конкретную гипотезу |
| Новое поведение/интеграция | brainstorming / writing-plans по масштабу и незакрытым решениям | Учитывать уже утверждённый план, не начинать Phase заново |
| Security review | Подходящий codex-security workflow по запрошенному виду аудита | Не запускать глубокий security scan на каждую правку документа |
| Skills / настройки Codex | openai-docs; skill-creator / writing-skills при реальном изменении skills | Глобальная правка влияет на другие проекты; статический аудит не является deployment |
| Windows VPN connectivity | Официальные клиентские evidence и bounded diagnostic plan | Само слово Windows не делает задачу разработкой WinUI; `winui-app` здесь не подходит |
| Схема БД AMN2 | Актуальный schema/migrations в production-репозитории | Не применять `sdp-firebird` без реального SDP/Firebird контекста |
| Мониторинг VPN-релизов | Уточнённый существующий monitoring workflow | Не восстанавливать устаревшие пути/автоматизации по памяти и не менять baseline без разрешения |

## Порядок дальнейшей оптимизации только в проекте

1. Сначала короткий проектный AGENTS.md: источник текущего статуса, область задачи,
   границы действий, правила выбора проверок и ссылка на эту карту. Не копировать
   тексты skills или изменчивый машинный каталог целиком.
2. Для docs-only задач оставить проверку фактов, ссылок, diff и секретов; для
   исправлений кода — конкретный RED/GREEN и релевантный итоговый набор. Не менять
   личные WinUI/Firebird skills ради того, чтобы они не срабатывали в чуждом контексте.
3. Если процессный skill предлагает лишние действия, зафиксировать точное правило
   и его конфликт с согласованной задачей; уточнять проектные инструкции, сохраняя
   ограничения среды. Плагины не редактировать, не переустанавливать и не отключать.
4. Проверка будущего AGENTS.md: понятен ли вход в Phase 16 без старых GO;
   не требует ли docs-only правка runtime-тестов; сохраняются ли TDD для code fix,
   approvals для live/push и отложенный статус iPhone/A/B. Это план проверки,
   не доказательство изменения поведения агента.

Safety-инварианты сохраняются: approvals на live/external writes, отсутствие
секретов в Git/логах, AWG2_UNTOUCHED, package016 immutable, один peer последовательно,
точный push SHA/origin/ref. Skill не может расширить пользовательское разрешение
или отменить ограничения среды. Пока остаются только рекомендации, не отключения.
