# Политика языков документации

## Решение

Все новые спецификации, планы, технические задания, инструкции и архитектурные заметки нужно готовить в двух языковых версиях:

- русский файл;
- английский файл.

Языки не смешиваются в одном документе, кроме коротких технических терминов, команд, имен файлов, API-названий и цитат из внешних инструментов.

## Правило именования

Для новых документов используется суффикс языка перед `.md`:

```text
docs/superpowers/specs/2026-05-27-feature-name.ru.md
docs/superpowers/specs/2026-05-27-feature-name.en.md
```

То же правило применяется к планам:

```text
docs/superpowers/plans/2026-05-27-feature-name.ru.md
docs/superpowers/plans/2026-05-27-feature-name.en.md
```

Для пользовательских инструкций:

```text
docs/NEXT_STAGE_BEGINNER_GUIDE.ru.md
docs/NEXT_STAGE_BEGINNER_GUIDE.en.md
```

## Что считать готовым

Документ считается готовым только если существуют обе версии:

- `.ru.md` с русским текстом;
- `.en.md` с английским текстом.

Содержание файлов должно совпадать по смыслу: структура, решения, требования, риски, команды и критерии приемки должны быть одинаковыми.

## Старые документы

Документы без языкового суффикса считаются legacy-документами. Их не нужно срочно переименовывать без отдельной задачи, но при существенной переработке их нужно разделить на две версии:

- `.ru.md`;
- `.en.md`.

## Рабочий порядок

1. Сначала готовится русская версия, если обсуждение задачи идет на русском.
2. Затем готовится английская версия в отдельном файле.
3. Перед завершением задачи проверяется, что обе версии добавлены или обновлены.
