# План реализации

## Этап 0. Решения перед кодом

- Выбрать ОС VPS для первого таргета: рекомендуется Ubuntu LTS или Debian.
- Выбрать платежный сценарий MVP: ручное подтверждение или конкретный провайдер.
- Решить, где будет жить бот: локально, на том же VPS, отдельный VPS.
- Подтвердить формат импортируемой ссылки для AmneziaVPN.

## Этап 1. Каркас проекта

- Создать Python-пакет.
- Добавить `pyproject.toml`.
- Добавить Dockerfile и Docker Compose.
- Настроить `.env.example`.
- Добавить базовую конфигурацию логирования.
- Подключить SQLite для MVP.

## Этап 2. Telegram-бот

- Настроить aiogram.
- Реализовать `/start`.
- Реализовать пользовательское меню.
- Реализовать админ-меню.
- Добавить allowlist администраторов.
- Добавить заявки на доступ.

## Этап 3. Модель данных

- Описать таблицы.
- Добавить миграции.
- Реализовать репозитории.
- Добавить audit log админских действий.

## Этап 4. AmneziaWG manager

- Реализовать генерацию keypair.
- Реализовать выделение IP.
- Реализовать сборку AmneziaWG 2.0 `.conf`.
- Реализовать QR-код.
- Реализовать добавление peer на сервер.
- Реализовать отзыв peer.

## Этап 5. Provisioning VPS

- Проверка ОС/kernel, первый целевой дистрибутив - Debian.
- Чтение `servers.yml`.
- Интерактивный режим, который спрашивает недостающие данные VPS и генерирует/обновляет `servers.yml`.
- Установка зависимостей.
- Установка AmneziaWG.
- Генерация UDP-порта больше `30000`, если порт не задан вручную.
- Открытие выбранного UDP-порта в `ufw`.
- Настройка network forwarding.
- Настройка firewall/NAT.
- Создание systemd-сервиса.
- Health check.

## Этап 6. Сроки и автоматизация

- Добавить планировщик.
- Отключать истекшие доступы.
- Отправлять предупреждения перед окончанием за 7, 5, 3 и 1 день.
- Создавать backup.
- Писать server health status.

## Этап 7. Платежи

- Сначала ручное подтверждение.
- Затем добавить выбранного payment provider.
- Добавить webhook или polling статусов.
- Связать заказ, платеж и peer.

## Этап 8. Мультисерверность

- Добавить несколько серверов.
- Добавить выбор локации.
- Добавить capacity и health checks.
- Добавить стратегию failover с выпуском нового конфига.

## Первый рабочий инкремент

1. Поднять пустого Telegram-бота.
2. Добавить регистрацию пользователя.
3. Добавить режим `ACCESS_MODE=free_test`.
4. Добавить создание устройства пользователя.
5. Сгенерировать тестовый `.conf` без записи на сервер.
6. Сгенерировать QR-код.
7. Добавить админское подтверждение заявки для режима `manual`.
8. Подключить реальное добавление peer на тестовом VPS.

## Уточненный MVP после принятых решений

- Первый provisioning target: Debian VPS.
- Бот разворачивается отдельно от VPN-сервера.
- Пользователь может иметь несколько устройств.
- Каждое устройство получает отдельный peer, IP, ключи, срок действия и конфиг.
- Максимум устройств на пользователя: 5.
- DNS клиента: `1.1.1.1`.
- Режим маршрутизации: full tunnel, `AllowedIPs = 0.0.0.0/0`.
- VPN-порт генерируется из диапазона больше `30000` и открывается в `ufw`.
- Базовый VPN-пул `10.8.0.0/24`, но IPAM должен поддерживать расширение пула или добавление серверов.
- Основной runtime AmneziaWG - без Docker, через systemd и `awg`/`awg-quick`.
- Несколько серверов в будущем управляются из одного Telegram-бота.
- Режим тестирования: бесплатная выдача доступов через `ACCESS_MODE=free_test`, но с обязательным подтверждением администратором.
- Тестовый срок по умолчанию: 7 дней.
- Ручное подтверждение и будущий платежный провайдер подключаются через общий слой `orders/payments`.
