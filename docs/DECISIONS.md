# Принятые решения

## Базовый контур MVP

- Первый VPN-сервер: собственный VPS.
- VPS уже есть, SSH-доступ доступен.
- ОС первого VPS: Debian.
- VPN-протокол: AmneziaWG 2.0.
- Telegram-бот работает отдельно от VPN-сервера.
- На первом этапе поддерживается один VPN-сервер.
- В будущем серверов может быть несколько, но управление всеми серверами должно идти из одного Telegram-бота.
- Архитектура должна заранее поддерживать будущие серверы, выбор локации и failover через выпуск нового конфига.

## Сеть

- VPN-порт должен генерироваться автоматически из диапазона больше `30000`.
- При provisioning выбранный UDP-порт нужно сразу открывать в `ufw`.
- Базовый VPN-пул для первого сервера: `10.8.0.0/24`.
- Адресный пул должен быть настраиваемым.
- Если ожидается больше 255 устройств/peer на сервер, нужно использовать более крупный пул, например `10.8.0.0/16`, или разбивать адресацию по серверам.
- Управление адресами должно работать через IPAM-слой, а не через ручной перебор строк в конфиге.
- DNS для клиентских конфигов: `1.1.1.1`.
- Режим маршрутизации: full tunnel, `AllowedIPs = 0.0.0.0/0`.

## Runtime AmneziaWG

- Основной путь для MVP: установка AmneziaWG 2.0 на хост Debian без Docker.
- Управление peer должно выполняться без перезапуска Docker-контейнеров.
- Предпочтительный runtime: `systemd` + `awg`/`awg-quick`.
- Добавление, отзыв и изменение peer должны применяться к работающему интерфейсу динамически, а затем сохраняться в серверный конфиг.
- Docker можно оставить как будущий альтернативный backend, но не делать его базовой зависимостью для управления peer.

## Доступы и устройства

- Один Telegram-пользователь может иметь несколько активных конфигов.
- Каждый конфиг соответствует отдельному устройству.
- Максимум устройств на одного пользователя в MVP: 5.
- Для каждого устройства создается отдельный peer, отдельный VPN IP и отдельные ключи.
- В пользовательской базе нужно хранить пользователя, дату создания пользователя и список его конфигов.
- Для каждого конфига нужно хранить дату создания, срок действия, дату окончания, IP и ключевые данные peer.

## Оплата

- В тестовом режиме все доступы бесплатные.
- MVP должен иметь простой переключатель режима оплаты.
- Первый рабочий режим: бесплатный тестовый доступ с обязательным ручным подтверждением администратором.
- Платежный провайдер будет выбран позже.
- Платежный слой должен быть абстрактным, чтобы позже подключить провайдера без переписывания Telegram-бота и VPN-логики.

## Сроки

Фиксированные сроки:

- 3 дня;
- 7 дней;
- 10 дней;
- 14 дней;
- 30 дней;
- 60 дней;
- 90 дней;
- 180 дней.

Также должен быть произвольный срок, задаваемый администратором.

Тестовый срок по умолчанию: 7 дней.

## Уведомления

Пользователя нужно предупреждать об окончании срока действия устройства за:

- 7 дней;
- 5 дней;
- 3 дня;
- 1 день.

## Развертывание

- Скрипты должны уметь разворачивать AmneziaWG 2.0 на чистом Debian VPS.
- Provisioning должен быть идемпотентным: повторный запуск не должен ломать уже настроенный сервер.
- Перед изменением серверного VPN-конфига нужен backup.
- Конфигурация серверов должна поддерживать два режима:
  - non-interactive: значения заранее заполнены в `servers.yml`;
  - interactive: мастер настройки спрашивает недостающие данные и генерирует/обновляет `servers.yml`.
- Новый VPS должен подключаться заменой значений в конфиге или прохождением интерактивного мастера.
