## Проверенные основания

- В `scripts/vps/phase16_controlled_stage_coordinator.py:699` application-stage предшествует runtime-stage. Это зависимость нашего координатора, а не самого AWG3.1.
- `scripts/vps/phase16_awg31_runtime_stage_remote.sh` использует отдельные Docker socket, контейнер, сеть, systemd unit и конфигурацию. Его runtime-операции не обращаются к БД приложения. Однако скрипт привязан к package 016, claim и package-root: готовым независимым установщиком он не является.
- Официальный образ `amneziavpn/amneziawg-go:3.1.20260814`, `linux/amd64`, имеет manifest digest `sha256:4e1fd2840f8d26eb6ec8bc1598e66f2f17f5d0201cd2baadbde560c104d4fc9d`. Опубликованные слои включают `amneziawg-go`, `awg`, `awg-quick`. Это проверка метаданных публикации, не запуск или проверка бинарников на Испании. [Docker Hub](https://hub.docker.com/layers/amneziavpn/amneziawg-go/3.1.20260814/images/sha256-4e1fd2840f8d26eb6ec8bc1598e66f2f17f5d0201cd2baadbde560c104d4fc9d?tab=layers).

Проверка текущего parser не доказывает состав конкретного установленного клиента. [Upstream config.c](https://github.com/amnezia-vpn/amneziawg-tools/blob/master/src/config.c).
- `scripts/vps/phase16_stage_support.py:118` создаёт намеренно минимальный server-only config без peers. В application source уже существует AWG3.1 client renderer. Их наличие не доказывает готовность согласованной пары сервер/клиент или прохождение трафика.

## Конкретный путь к первому тесту

1. Отдельный небольшой runtime-only сценарий: готовый закреплённый образ и штатные инструменты, без application-stage, SQLite, бота и собственного ZIP/stdin bootstrap. Передача файлов — штатный SFTP/SCP, с проверкой хешей и host key.
2. Одна согласованная серверная/клиентская конфигурация для одного оператора. Проверять её штатным parser, а не только сравнением строк в наших тестах; никаких настоящих ключей в тестовых выводах, Git или квитанциях.
3. Перед live — свежая проверка совместимости хоста, dedicated Docker, TUN, свободных ресурсов и границ отката. Затем отдельное точное разрешение на установку/одного peer; старые approval и transaction 007 не переиспользуются.
4. Первый живой тест на АРМ/Windows: handshake, трафик, DNS, reconnect и качество связи. Проверки Android/iPhone и интеграция AMN2 следуют после этого; пилот не равен общей готовности выдачи.

Следующая локальная работа: реализовать только пункт 1 и безопасную подготовку пункта 2, с узкой проверкой совместимости. Не создавать новый полный package и не продолжать отладку старого transport ради этого пилота.

## Границы результата

Package 016, его freshness/approval/rollback-контракты и прежние результаты не меняются. AWG2 не удаляется и не перенастраивается. Этот документ не отменяет quality/acceptance gate и не разрешает общую выдачу.

В этом шаге не выполнялись SSH, Spain egress, установка, stage, создание ключей/peer/config, тестовые прогоны, materialization или verifier. К серверу не обращались; его последнее сохранённое состояние не объявляется свежим. Изменяется только эта локальная заметка.
