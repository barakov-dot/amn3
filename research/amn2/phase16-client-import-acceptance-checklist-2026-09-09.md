# Проверка имени при импорте — три клиента

Подготовлено 2026-09-09; обновлено 2026-09-11. Статус: PARTIALLY_EXECUTED.
Это проверочный лист к [исследованию](phase16-client-import-naming-research-2026-09-08.md),
не новый execution plan и не разрешение установки, подключения или выдачи.
Export source: AMN2 b3ed202ba118adb36c474eab5722065ea420d274.

## Условия начала

Использовать отдельно подготовленную среду без рабочих VPN-профилей, с отключённой
сетью и без автоматического подключения. Изоляция должна быть подтверждена до
импорта; отдельное окно приложения не означает отдельное хранилище профилей.
Не импортировать в существующее рабочее хранилище и не менять его настройки.
Фиксировать ОС, версию и официальный источник конкретной сборки. Для DefaultVPN
соответствие dev-исходника установленной сборке пока не установлено.

Только синтетическая fixture: синтаксически корректные тестовые ключи, никогда
не используемые на сервере, endpoint из документационного диапазона и явно
заданные DNS, MTU, AllowedIPs, keepalive и поддерживаемые AWG-поля. Старые fixtures
с текстовыми placeholders могут быть отвергнуты клиентом до проверки имени;
такой отказ не доказывает дефект envelope. Реальные ключи и профили не нужны.
Синтетическая fixture материализована и использована в Windows Sandbox; см. результат ниже.

## Матрица и последовательность

| Клиент | Вход | Ожидаемое имя | Отдельная проверка |
| --- | --- | --- | --- |
| AmneziaVPN | Родной Amnezia envelope через поддерживаемый импорт файла/ссылки | Neobyatnaya.NET | description, сохранение всех параметров |
| AmneziaWG | Neobyatnaya.NET.conf | Neobyatnaya.NET | basename, точка, длина 15; каждая ОС отдельно |
| DefaultVPN | Родной Amnezia envelope через доступный в сборке импорт | Neobyatnaya.NET | MTU: dev-исходник подставляет default; не считать имя доказательством совместимости |

1. Зафиксировать пустое тестовое хранилище и версии. Если изоляция не доказана — STOP.
2. Импортировать один синтетический артефакт без подключения. Записать фактический
   заголовок; не переименовывать вручную ради PASS. Подпись протокола оценивается отдельно.
3. Сравнить доступные сохранённые/экспортированные параметры с исходной fixture:
   endpoint, адреса, DNS, MTU, AllowedIPs, keepalive, ключевые поля и все AWG-поля.
   Секретные значения в отчёт не включать: достаточно equality/difference/unknown.
   Невидимое поле без поддерживаемого readback получает UNKNOWN, не PASS.
4. Повторить импорт в той же одноразовой среде. Зафиксировать отказ, новый объект,
   суффикс или перезапись. Не подтверждать перезапись. Это отдельная проверка
   поведения приложения, а не доказательство работы existing_names экспортера.
5. Закончить без подключения. Очистка допускается только для точно идентифицированных
   синтетических объектов в одноразовой среде; рабочие профили не затрагивать.

## Критерии и результат

Для каждой ОС/версии независимо записать: input format; import result;
exact_name PASS/FAIL; parameter_preservation PASS/FAIL/UNKNOWN;
duplicate_behavior; connected=false; evidence reference.

Имя PASS только при точном Neobyatnaya.NET после первого импорта без ручной правки.
Изменение MTU или другого параметра означает FAIL сохранности при возможном PASS имени.
Недоступная сборка/UI/изоляция означает NOT_RUN; неподтверждённое поле — UNKNOWN.
Даже полный PASS этого листа не доказывает connectivity или quality и не включает
новый формат в delivery handlers. Решение об интеграции принимается после результатов.
