# Phase 16 — клиентский кандидат Jc/I1 для АРМ

Дата: 2026-08-29.

## Наблюдавшийся отказ

Оператор отдельно проверил профили `ES-AWG31-PILOT-DNS1` и
`ES-AWG31-PILOT-DNS2`: AmneziaVPN 5.0.1.5 показывал подключение, но доступа в
интернет не было. За эти две попытки read-only серверное наблюдение показало:

- received: +958558 байт;
- sent: +680170 байт;
- RX: +1620 пакетов, errors/dropped = 0;
- TX: +1298 пакетов, errors/dropped = 0;
- контейнер, интерфейс, UDP 30002, forwarding и NAT оставались исправны.

Следовательно, это не мёртвый endpoint и не отсутствие двустороннего обмена.
Локальный автономный watcher не увидел ожидаемый адрес `10.212.13.2`, поэтому
он не дал достоверного Windows-замера DNS/HTTPS; этот результат нельзя считать
доказательством отказа DNS.

## Сужение причины по официальным источникам

- Официальная инструкция Amnezia для случая «подключение есть, трафика нет»
  предлагает клиентскую проверку с `Jc = 6` и непустым `I1`:
  https://docs.amnezia.org/troubleshooting/self-hosted-amneziawg-not-working/
- Импортёр AmneziaVPN 5.0.1.5 принимает AWG3-поля из native `.conf`, но
  отображаемое имя назначает через `nextAvailableServerName()`, а не из имени
  файла:
  https://github.com/amnezia-vpn/amnezia-client/blob/5.0.1.5/client/core/controllers/selfhosted/importController.cpp
- Список ключей 5.0.1.5 включает `Jc/Jmin/Jmax`, `I1-I5`, S/H,
  `HeaderProtectionKey` и остальные используемые AWG3-поля:
  https://github.com/amnezia-vpn/amnezia-client/blob/5.0.1.5/client/core/utils/constants/configKeys.h

Порт 30002 выше 9999; официальная инструкция отдельно отмечает возможную
фильтрацию таких портов. Это следующая, а не параллельная гипотеза: менять порт
можно только если клиентский Jc/I1-тест не даст интернет.

## Подготовленный однофакторный кандидат

Исходник: защищённый `Spain-AWG31-ARM-DNS9-DUAL.conf`, SHA-256
`85a7d02205da399bfc27b3030d104c7e836791e5bbd877549714cc82f2d02d3c`.

Новый защищённый файл: `ES-AWG31-PILOT-DNS2-JC6-I1.conf`, SHA-256
`66afe3784b4b16148c4fbd252a8cffe3a4f7da889ce412f827afcd817cef8146`.

Проверенный diff содержит ровно четыре клиентских ключа: `Jc`, `Jmin`,
`Jmax`, `I1`. Все остальные байты профиля совпадают с DNS2; ACL совпадает;
старые файлы не перезаписаны. Новый генератор привязан к SHA-256 источника,
создаёт файл только через exclusive create и не выводит ключевой материал.

## Следующий тест

1. Импортировать новый файл как отдельный профиль.
2. В приложении вручную назвать его `ES-AWG31-PILOT-DNS2-JC6-I1`, поскольку
   native `.conf` не управляет отображаемым именем в 5.0.1.5.
3. Убедиться, что остальные VPN-профили отключены.
4. Подключить кандидат на 30 секунд, открыть обычный HTTPS-сайт, затем
   отключить его. Сообщение во время включённого VPN не требуется.

Сервер, пилотный runtime, package 016 и AWG2 этим шагом не изменялись.

## Фактический результат и граница отказа

На Windows 11 с AmneziaVPN 5.0.1.5 профиль подключался, однако доступа в
интернет не давал. Локальный read-only watcher при этой попытке не увидел
создания стандартного tunnel adapter, адреса или маршрутов; в системном журнале
при этом было событие установки динамической службы `Amnezia VPN (tunnel)`,
которая после попытки отсутствовала. Это согласуется с отказом клиентского
tunnel integration, а не с отказом удалённого AWG3.1 runtime.

После отключения Windows-профиля оператор последовательно импортировал тот же
checksum-bound профиль на Android-проектор. YouTube воспроизводит видео через
подключение. Это подтверждает реальный прикладной HTTPS/streaming-трафик и
функциональность server peer/config, UDP 30002, forwarding/NAT и DNS/reachability
на клиенте не-Windows. Проверка не является полным замером пропускной
способности, потерь или долговременной стабильности.

Read-only серверное наблюдение после Windows-теста также показало рост счётчиков
на 476324 / 352054 байт и 772 / 636 пакетов без errors/dropped. UDP 443 уже
имеет host listener, несколько nft-правил и не имеет свободной выделенной Docker
привязки для пилота, поэтому перенос пилота на UDP 443 не обоснован и создаст
конфликт. Следующая работа разделяется: последовательная проверка того же
профиля на iPhone и отдельная bounded-диагностика Windows-клиента. Серверный
профиль, порт и AWG2 до новых доказательств не меняются.
